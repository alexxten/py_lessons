**Тема:** Разработка универсального генератора таблиц из словаря-схемы.
**Цель:** Создать инструмент, который в будущем сможет автоматически создавать таблицы на основе структуры JSON-ответа от внешнего API.

---

## 1. Контекст и связь с будущим заданием
В следующей задаче нам предстоит получать данные от REST API (например, список пользователей, товаров или заказов) и сохранять их в PostgreSQL. Ответы API часто приходят в виде списка словарей (`list[dict]`).

Нам нужно создать утилиты, которые:
1. Анализируют плоский словарь (одна запись) или список словарей.
2. Строят по ним SQL-схему, автоматически подбирая типы данных.
3. Создают таблицу в БД (двумя способами: сырой SQL и ORM).

## 3. Общие требования

В идеале вообще сделать отдельный репозиторий, но можно отдельной директорией в этой репе.

1. **Абстракция:** Вся логика преобразования метаданных в SQL должна быть вынесена в отдельные функции (см. п. 4).
2. **Обработка "сырых" данных:** На вход может подаваться **один** словарь или **список словарей**. Скрипт должен сам определить тип входных данных и извлечь структуру.
3. **Сохранность:** Предусматриваем, что при повторном запуске таблица не пересоздается (логика `IF NOT EXISTS`).
4. **Безопасность:** Обязательное экранирование имен таблиц и колонок.
5. **Структура проекта:**
```
project/
├── type_mapper.py # Общая логика определения типов
├── create_psycopg.py # Реализация через psycopg2
└── create_alchemy.py # Реализация через SQLAlchemy
```

## 4. Конкретные задания

### 4.1. Разработка "Инференсера" типов
**Файл:** `type_mapper.py`

Создаем функцию `infer_pg_type(value) -> str`, которая на основе Python-объекта возвращает строку с типом PostgreSQL:

| Python-тип | PostgreSQL-тип |
|------------|----------------|
| `int`      | `INTEGER`      |
| `float`    | `DECIMAL(15, 2)` |
| `bool`     | `BOOLEAN`      |
| `str`      | `TEXT`         |

**Требования к функции:**
- Функция должна обрабатывать все перечисленные типы.
- Для строк, похожих на дату/время (формат `YYYY-MM-DD HH:MM:SS`), возвращаем `TIMESTAMP`.
- Для всех остальных случаев (включая `None`) возвращаем `TEXT`.

Создаем функцию `extract_schema(data) -> dict`, которая:
- Принимает на вход `dict` или `list[dict]`.
- Если передан `dict` — возвращает его как есть.
- Если передан `list[dict]` — объединяет все ключи из всех словарей, сохраняя только уникальные имена колонок.
- Если список пуст или передан пустой словарь — выбрасывает исключение с понятным сообщением.

**Пример работы:**
```python
# Для одной записи
schema = extract_schema(sample_record)
# -> {'user_id': 101, 'full_name': 'Alice Smith', ...}

# Для списка записей
schema = extract_schema(sample_records)
# -> {'user_id': 101, 'full_name': 'Alice Smith', ...}  # берем первую запись для типов
# Но учитываем, что в разных записях могут быть разные ключи
```

### 4.2. Генератор SQL-запроса (psycopg2)
**Файл:** `create_psycopg.py`

1. Импортируем `infer_pg_type` и `extract_schema` из `type_mapper.py`.
2. Создаем функцию `generate_create_table_sql(table_name: str, data) -> str`, которая:
   - Использует `extract_schema` для получения структуры данных.
   - Использует `infer_pg_type` для определения типа каждой колонки.
   - Добавляет суррогатный первичный ключ `id SERIAL PRIMARY KEY` (так как в данных из API его может не быть).
   - Возвращает готовый SQL-запрос с `IF NOT EXISTS`.
3. В основном блоке (`if __name__ == "__main__":`):
   - Подключаемся к БД через `psycopg2`.
   - Выполняем сгенерированный запрос.
   - Выводим в консоль информацию о созданных колонках и их типах.
   - Обрабатываем возможные исключения (подключение, синтаксис SQL).

**Пример вывода в консоль:**
```Обнаружено 7 колонок в структуре данных
Колонка 'user_id' -> INTEGER
Колонка 'full_name' -> TEXT
Колонка 'email' -> TEXT
Колонка 'age' -> INTEGER
Колонка 'is_active' -> BOOLEAN
Колонка 'salary' -> DECIMAL(15,2)
Колонка 'registration_date' -> TIMESTAMP
Таблица 'users' успешно создана (или уже существует).
```

### 4.3. Динамическая модель (SQLAlchemy)
**Файл:** `create_alchemy.py`

1. Импортируем `infer_pg_type` и `extract_schema` из `type_mapper.py`.
2. Создаем функцию `get_sa_type(pg_type: str)`, которая транслирует строку PostgreSQL-типа в соответствующий класс SQLAlchemy:
   - `INTEGER` → `Integer`
   - `BOOLEAN` → `Boolean`
   - `DECIMAL(15,2)` → `Numeric(15, 2)`
   - `TIMESTAMP` → `DateTime`
   - `TEXT` → `String` (или `Text`)

3. Создаем функцию `create_dynamic_model(table_name: str, data)`, которая:
   - Использует `extract_schema` для получения структуры данных.
   - Определяет типы для каждой колонки через `infer_pg_type`.
   - Транслирует их в типы SQLAlchemy через `get_sa_type`.
   - Динамически генерирует класс модели через `type()`, добавляя поле `id` как первичный ключ.
   - Возвращает созданный класс модели.

4. В основном блоке:
   - Создаем engine для подключения к БД.
   - Генерируем модель с помощью `create_dynamic_model`.
   - Выполняем `Base.metadata.create_all(engine)`.
   - Выводим информацию о созданных колонках (аналогично п. 4.2).

## 5. Требования к коду (подготовка к API)

1. **Переиспользование:** Функции `infer_pg_type` и `extract_schema` должны быть вынесены в отдельный файл `type_mapper.py` и импортироваться в оба скрипта.
2. **Логирование:** Добавляем `print()` с информацией о том, какой тип был присвоен каждой колонке. Это поможет отлаживать структуру незнакомых API. Но лучше юзать не принт, а логгирование библиотекой loguru.
3. **Обработка крайних случаев:** 
   - Если передан пустой список или пустой словарь, скрипт должен выдать понятное предупреждение и завершиться.
   - Если в разных записях есть разные ключи, схема должна объединять их все.
4. **Документация:** Каждая функция должна содержать docstring с описанием параметров и возвращаемого значения.
5. **Стиль кода**: для форматирования кода использовать `black` или `ruff`
